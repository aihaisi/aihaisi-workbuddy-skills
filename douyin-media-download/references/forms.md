# 抖音作品形态判别与处理

渲染拿到 DOM 后，**先判形态，再走提取**。判别优先级：实况图 > 图+视频混合 > 纯视频。
纯视频由 `scripts/dy_fetch.sh` 全自动处理；本文档覆盖另外两种形态。

## 形态速查

| 形态 | DOM 特征 | 提取路径 |
|---|---|---|
| 纯视频 | `douyinvod` 直链 + 有视频流 | 脚本全自动 |
| 实况图（LivePhoto） | `livePhoto` 关键字命中；图片数组里藏 N 段 douyinvod 视频地址 | 每张图下有一段 3s 左右循环视频层，逐段抽出转 GIF |
| 图+视频混合 | 同时有 `"images"` / `downloadUrlList` 和 douyinvod 直链；时长可能只有几秒但音频 90s+ | 图走 `images[].urlList`，视频走 douyinvod；两者都交付 |
| 纯图文 | 只有 `images` 数组，无 douyinvod | 下载 urlList 里的原图即可 |
| 音频坑 | 下载成功但 ffprobe 只有 audio 流 | 第一个 playAddr 是背景曲 M4A，换下一条直链 |

## 实况图（LivePhoto）处理规则

1. **凡是 slides/图文页，必须先 grep `livePhoto` 并数 douyinvod 地址数量**，确认没有动态层才能当静态图交付——漏检实况图是最容易翻车的点。
2. 图片数组本身**不带** livePhoto 标记，必须主动搜关键字。
3. N 张图可能对应 N 段独立的循环视频（地址各不相同），逐段下载、逐段 ffprobe 断言视频流。
4. 交付时 GIF（动态版）+ 静态原图都要给。

## 图+视频混合案例（实测）

《可以跟我去散步吗》：作品形态是 note（图文），实际是 3.6s 视频套 90s 背景音频。
- 按 note 页渲染，音频和视频分属不同存储桶；
- ffprobe 发现音频 90s / 视频流 3.6s 时，按视频流处理，不要被时长吓住；
- GIF 按视频流时长转。

## 通用铁律（所有形态共用）

1. 特征定位，不写死索引/JSON 键名——数据位置每次都可能变（实测见过第 188、194 号 script 块、`<video><source>` 标签三种）。
2. 转义层数不固定（`\u0026`、`\"` 嵌套），迭代解到干净 URL 为止，别指望一次替换。
3. 直链即取即下，签名几分钟过期。
4. 每个下载产物过 ffprobe，人肉不参与断言。
5. 批量跑加间隔与重试，触发验证码就停。
