# 三个仪器：用法、阈值来源、实测读数

> 目录：`scripts/motion_profile.py` · `motion_map.py` · `check_motion.py`
> 依赖：ffmpeg + numpy + PIL（`check_motion.py` 的掩码模式另需 scipy）

---

## 0. 先记住三条使用纪律

1. **必须与对标作品并排跑。** 单独一个数不构成主张 —— 这些指标没有绝对好坏，只有"和这个赛道的合格品比"。
2. **`motion_profile` 会漏掉最关键的诊断。** 它只给标量；"动的区域太小"只有 `motion_map` 的**热力图**能看出来。两个一起跑。
3. **改动检测逻辑后必须重跑已知样本**（§4）。否则分不清"产品的问题"和"仪器的锅"。

## 1. `motion_profile.py` —— 动效密度画像

```bash
python motion_profile.py <视频> [<视频> ...]
```

**做法**：按 5fps 抽帧 → 缩到 320 宽灰度 → 算相邻帧平均绝对差（MAD）→ 出分布统计。

| 输出列 | 含义 | 读法 |
|---|---|---|
| 中位 | 常年处于什么变化水平 | 高 = 元素持续运动；低 = 大部分时间静止 |
| 均值 | 整体变化量 | 主指标 |
| p10 | 地板 | 极低 = 有大量"几乎没动"的帧 |
| p90 | 高峰 | 低 = 没有强冲击的瞬间 |
| 静止比 | MAD < 0.20 的帧占比 | 高 = 死屏时间多 |

**「近静止比」的阈值 0.20 是怎么来的**：320px 灰度下，真正静止的两帧（只剩 H.264 噪声）
实测 MAD < 0.15 ⇒ 0.20 是安全阈值。

### 1.1 实测对标表（同赛道，1920×1080 横屏）

| 作品 | 中位 | 均值 | p10 | p90 | 静止比 | 变化>0.2 像素占比 |
|---|---|---|---|---|---|---|
| 对标 · 某 56 万赞作品 | 0.889 | **2.721** | **0.245** | **4.24** | **5.9%** | **100.0%** |
| 对标 · 另一条 | 0.767 | 2.115 | 0.155 | 5.09 | 13.4% | — |
| 对标 · 另一条 | 0.518 | 2.351 | 0.135 | 5.82 | 23.1% | — |
| 对标 · 另一条 | 2.646 | 5.721 | 0.314 | 16.29 | 7.5% | — |
| **我们 · 旧片（无动态背景）** | 0.575 | **1.285** | **0.009** | **2.808** | **26.0%** | **69.5%** |
| **我们 · 加全屏颗粒后** | 1.213 | **1.772** | **0.635** | **2.956** | **0.0%** | **100.0%** |

**这张表把结论说得很清楚**：加颗粒把 p10（0.009 → 0.635）和静止比（26% → 0%）**修好了**，
把覆盖率从 69.5% 拉到 100%；但**均值（1.285 → 1.772）和 p90（2.808 → 2.956）几乎没动**，
仍低于对标线（2.0 / 4.0）。

⇒ **颗粒只抬地板，不造高峰。** 它抹平了动态范围。想让 p90 上去，只能让**主体更大 / 更立体 / 动得更实**。

**验收线**：均值 ≥ 2.0 ｜ p90 ≥ 4.0 ｜ p10 ≥ 0.13 ｜ 近静止比 ≤ 13% ｜ 覆盖率 100%。

## 2. `motion_map.py` —— 运动分布热力图

```bash
python motion_map.py <视频> <输出png> [标签]
```

**做法**：逐帧算 `|frame_i − frame_{i−1}|`，再沿时间取平均 ⇒ 一张与画面同尺寸的图。
亮 = 这块区域常年变化；黑 = 这块区域从不变化。

**它是"像 PPT"的唯一直接证据。** 典型症状：
亮区只堆在画面中间，**四角与四周大片纯黑** ⇒ 约 30% 的画面从来没变过。

🔴 **根因是物理事实，不是"动得不够"**：
**平色区域无论怎么平移、缩放，逐帧差异都是 0。**
所以"让元素动起来""加镜头推拉"救不了这些黑区 ——
必须放一层**覆盖全屏、有高频结构**的东西（星野视差、颗粒滚动、细网格…）。

**顺带量到一个常用数**：我们的内容通常**只占画面 5.6%–21.3%**（`check_motion.py` 会打印内容占比）。
八成以上是背景 —— 想让 p90 上去，只能让主体更大。

## 3. `check_motion.py` —— hold 段冻结检测

```bash
python check_motion.py <mp4> <帧号,逗号分隔> [--bg-dir <纯背景帧目录>] [--no-bg]
```

检查窗口：每个检查点往前取连续 **5 帧**（即传每章的**最后一帧**）。

### 3.1 判据来源

| 量 | 实测值 |
|---|---|
| 源帧平移 1px | MAD ≈ **0.8367** |
| H.264 压缩噪声 | MAD ≈ **0.005** |
| ⇒ 有意义运动的下限 | **0.05** |

### 3.2 为什么必须是「内容区掩码」

| 做法 | 结果 |
|---|---|
| 看全帧 | 纯背景自身帧间 MAD ≈ 2.15 ⇒ 成片 hold 段读数被抬到 1.4–2.1 ⇒ **真冻结也"通过"** |
| 扣背景基线 | 背景参考帧全帧都是颗粒，成片里大片被不透明内容盖住 ⇒ 相减全为负（−0.03 ~ −0.69）。**负残差不代表"没动"，代表"减错了"** |
| ✅ 内容区掩码 | 内容像素上颗粒被遮住 ⇒ 量到的就是纯资产运动，什么都不用减 |

```
内容掩码 = |成片帧 − 纯背景帧| > 16 灰阶
掩码     = 向内腐蚀 4 像素          ★ 不能省
净运动   = 掩码内相邻帧差均值        阈值 0.05
```

### 3.3 🔴 腐蚀这一步是怎么发现的（完整证据链）

用**已知冻结**的合成样本（内容块逐帧位置完全相同、背景照常滚动）跑：

| 掩码处理 | 净运动 | 判定 |
|---|---|---|
| 不腐蚀 | 0.0776 | ❌ 误判为**通过** |
| 腐蚀 4px | **0.0012** | ✅ 正确判出**冻结** |

逐像素解剖（同一对帧）：
- 白块**内部**：帧间 MAD **0.0001**
- 掩码的**边界环**：帧间 MAD **0.7391**，只占掩码 10.5%，却贡献读数 ~98%
- 边界环是「半覆盖」的抗锯齿像素 —— 那里背景颗粒露在外面照样在动

⇒ **边界环会系统性污染读数**，必须腐蚀掉。

⚠️ 腐蚀也会吃掉**细笔画**（文字/细线）。所以内容如果大量是细笔画，
腐蚀后的掩码可能只剩很少的像素 —— 这时读数仍然有效（它测的是"幸存的实心内容"），
但**内容占比会掉到很低**，需要人工看一眼是不是还覆盖着有意义的内容。

### 3.4 一次取多帧：别逐帧调 ffmpeg

```bash
# ✗ 对每个帧号单独跑一次 —— 每次都从头解码，几十个点会到分钟级 / 被超时杀掉
ffmpeg -i in.mp4 -vf "select=eq(n\,385)" -vframes 1 f385.png   # 反复做 N 次

# ✓ 一次解码 + select 多帧
ffmpeg -i in.mp4 -vf "select=eq(n\,385)+eq(n\,386)+eq(n\,387)" -vsync 0 f%05d.png
```

⚠️ `-vsync 0` 输出的是**顺序编号**，不是原始帧号。
第 k 个文件对应排序后帧号列表的第 k 项；**数量对不上必须降级重取**，
否则帧号整体错位 —— 错位后读数看起来仍然"合理"，极难发现。

### 3.5 纯背景参考帧怎么生成

前提：背景被设计成**全局帧号的确定性函数**（如 canvas 里 `drawBackground(ctx, W, H, f)`）。

1. 做一个"只画背景、不画内容"的页面（复刻 `drawBackground` 的调用）。
2. 用管线的截图工具，按**成片同样的全局帧号**渲染一批图，命名 `f%05d.png`，放进一个目录。
3. 传给 `--bg-dir`。

⚠️ **绝不能传章内帧号** —— 背景吃全局帧号，传章内帧号会让每章开头跳回去，参考帧全错。

⚠️ 没有动态背景的旧片用 `--no-bg`（全帧读数仍然可信）。
若给了 `--bg-dir` 但目录里没有匹配文件，脚本会**降级成看全帧并打印警告** ——
**别把"降级"读成"通过"**。

## 4. 已知样本的构造（改检测逻辑后必做）

```bash
# ① 用纯背景帧当底，贴一块逐帧位置完全相同的静态内容
python - <<'PY'
import numpy as np, os
from PIL import Image
os.makedirs('frz', exist_ok=True)
for i, f in enumerate(range(BG0, BG0 + 5)):
    a = np.asarray(Image.open(f'bg/f{f:05d}.png').convert('RGB')).copy()
    a[400:700, 700:1200] = (240, 240, 240)      # 静态内容块
    Image.fromarray(a).save(f'frz/f{i:05d}.png')
PY

ffmpeg -y -framerate 30 -i frz/f%05d.png -c:v libx264 -pix_fmt yuv420p -crf 18 frozen.mp4

# ② 必须判 ❌
python check_motion.py frozen.mp4 "5" --bg-dir bg

# ③ 反向：拿一段已知在动的片段，必须通过
```

🔴 **两个坑**：
1. **合成样本的帧号必须与背景参考帧号对齐。** 合成片段重编号成 0..4、而背景是按别的帧号渲染的，
   检测器会**正确地降级**成看全帧 —— 你会把"降级"误读成"检测器失效"。
2. **只做单向（冻结样本）不够。** 还要拿一段已知在动的片段确认它会通过，
   否则一个"永远报冻结"的检测器也能通过第一项。

## 5. 一次真实的检出记录（可作为"检测器该有多敏感"的标尺）

某条片：10 章，每章取末尾 5 帧。

| 章 | 内容占画面 | 内容区净运动 | 判定 |
|---|---|---|---|
| 1 | 6.2% | 0.4129 | OK |
| 2 | 8.2% | 0.3291 | OK |
| **3** | 1.5% | **0.0068** | ❌ 冻结 |
| 4 | 8.6% | 0.3199 | OK |
| 5 | 14.3% | 0.3078 | OK |
| 6 | 1.0% | 0.5623 | OK |
| **7** | 1.7% | **0.0018** | ❌ 冻结 |
| 8 | 8.6% | 0.3215 | OK |
| 9 | 10.4% | 1.3536 | OK |
| 10 | 8.1% | 0.3623 | OK |

**第 3、7 章是真冻结**，核实方式：
- 目视两帧（相隔 3 帧）**内容逐像素一致** —— 标题、卡片、字幕都没动，只有背景颗粒在变。
- 对两帧分别减纯背景，取**沿 y 平均的横向剖面**：两帧剖面峰值的**位置完全相同**
  （差 0.1 灰阶）；而对照组（运动明显的章）同一剖面峰值在 4 帧内移动了 500+ px。
  ⇒ 仪器**能**看见移动的东西，这两处是真的没动。

🔴 **旧检测器（不腐蚀）对这两处给出 0.1479 / 0.1445，判"通过"。**
那 0.14 全部来自边界环的颗粒漏光，不是内容在动 ——
这是"检测器被背景喂饱"的第二层：**不是全帧被喂饱，而是掩码边界被喂饱。**

⚠️ **这两章的形态值得记一笔**：都是「终端卡」资产 —— 文字打完就停了，
设计里那条柔光带只有 alpha 0.085、宽 620px、每帧移 22px ⇒
**任一像素每帧只变化约 1–2 灰阶**，既过不了判据，观众也基本察觉不到。

⇒ **修 hold 冻结要动内容本身**（光标闪、数值滚动、某行重打、元素呼吸），
不要指望"加一条淡光带"就能续命。**"持续在动"和"动得能被察觉"是两件事。**
